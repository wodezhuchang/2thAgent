## 1. 知识库总览

| 项 | 说明 |
|---|---|
| 数据源目录 | `D:\2thAgent\knowledge_base\`（含评课细则、课标、微格评课量表、优秀试讲案例） |
| 向量库路径 | `D:\2thAgent\backend\data\chroma\` |
| 集合名 | `trial_evaluation_rules` |
| Embedding 模型 | `BAAI/bge-small-zh-v1.5`（首次需下载，见 §5） |
| 管理器脚本 | `D:\2thAgent\backend\app\scripts\kb_manager.py` |

| OCR（扫描 PDF） | RapidOCR（onnxruntime）+ PyMuPDF（页渲染）自动回退 |

### 1.1 数据源与自动分类

`kb_manager.py` 会**递归扫描** `knowledge_base/` 下所有 `.md/.txt/.pdf` 文件，并根据**文件名关键词**自动分类（不依赖目录结构）：

| doc_type | 触发关键词（文件名含） | 例 |
|---|---|---|
| `curriculum` | 课程标准、课程方案 | 义务教育数学课程标准2022年版.pdf |
| `rubric` | 评价、量表、评分、考核、评课 | 临沂大学_微格教学评价…评价表.pdf |
| `case` | 教学设计、试讲案例、教学案例、说课 | 初中_语文_教学设计_背影.md |
| `rule` | 细则（评课细则专用） | 评课细则知识库语料_v1.0.md |

**自动排除**：文件名含"可信链接清单/链接清单/readme/说明"的文档（纯链接清单，无实质正文，不入库）。

### 1.2 向量库内部结构（Chroma）

- 每个文档被切块（chunk，滑动窗口约 220 字 + 30 字重叠），每条 chunk 一行。
- 每个 chunk 带**元数据**：`doc_type`、`subject`（学科）、`source_file`（相对路径）、`file_hash`（文件内容哈希，用于变更检测）、`title`、`chunk_index`；评课细则还带 `indicator`/`indicator_name`。
- 元数据作用：支持按类型/学科过滤检索、支持增量去重、支持追溯来源。

## 2. 常用操作命令（核心）

> 所有命令在 PowerShell 中执行，先设置模型镜像（如无法直连 huggingface）：
> ```powershell
> $env:HF_ENDPOINT="https://hf-mirror.com"
> ```

| 操作 | 命令 |
|---|---|
| **首次/增量写入数据库** | `& "D:\2thAgent\backend\.venv\Scripts\python.exe" "D:\2thAgent\backend\app\scripts\kb_manager.py" --update` |
| **全量重建（清空重来）** | 同上但参数为 `--rebuild` |
| **查看已入库状态** | 同上但参数为 `--status` |
| **检索** | 同上但参数为 `--search "查询词"` |
| **按类型过滤检索** | 追加 `--doc_type curriculum`（或 `rubric`/`case`/`rule`） |
| **按学科过滤检索** | 追加 `--subject 数学` |
| **指定返回条数** | 追加 `--top 8` |
| **清空向量库** | 参数为 `--clean` |

**速查示例**：
```powershell
$env:HF_ENDPOINT="https://hf-mirror.com"
$py = "D:\2thAgent\backend\.venv\Scripts\python.exe"
$mgr = "D:\2thAgent\backend\app\scripts\kb_manager.py"

& $py $mgr --update                                   # 写入/更新全部文档
& $py $mgr --status                                   # 查看 50 个文档的入库统计
& $py $mgr --search "数学新授课导入环节怎么设计"        # 综合检索
& $py $mgr --search "板书错别字" --doc_type rule        # 只查评课细则
& $py $mgr --search "课标对数学素养要求" --subject 数学   # 只查数学课标
```

## 3. 增量更新机制（怎么加新资料/改资料）

`--update` 是**增量**的，逻辑如下：

```
扫描 knowledge_base 下所有文档
对每个文档：
  计算文件内容哈希 file_hash
  已在库里且哈希相同？  → 跳过（不重复入库）
  已在库但哈希不同？    → 删除该文件的旧块，重新入库（覆盖更新）
  新文件？            → 直接入库（追加）
```

**所以日常维护只需两步：**
1. **加新资料**：把新的课标/量表/案例 PDF 或 MD 文件直接放进 `knowledge_base/`（任意子目录），文件名按 §1.1 关键词命名以便正确分类；
2. **跑一次 `--update`**：新文件自动追加，改过的文件自动覆盖更新，没变的文件跳过。

> 关键：**不要手动清库**。增量机制会自动处理新增/变更/去重。只有确认要推倒重来时才用 `--rebuild`。

## 4. 复现重建步骤

要在另一台机器（或环境重装后）完整复现知识库：

1. **还原源码与资料**：确保 `knowledge_base/`（全部 PDF/MD）与 `backend/app/scripts/kb_manager.py` 就位；
2. **建环境装依赖**：
   ```powershell
   cd D:\2thAgent\backend
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install chromadb sentence-transformers numpy pypdf PyMuPDF rapidocr-onnxruntime fontTools
   ```
3. **下载模型**（首次）：设 `$env:HF_ENDPOINT="https://hf-mirror.com"`；
4. **重建向量库**：
   ```powershell
   & "D:\2thAgent\backend\.venv\Scripts\python.exe" "D:\2thAgent\backend\app\scripts\kb_manager.py" --rebuild
   ```
5. **验证**：`--status` 看到全部文档已入库；`--search "试讲评价"` 能返回相关片段。

## 5. 依赖与环境说明

| 依赖 | 用途 | 版本（实测） |
|---|---|---|
| python | 运行时 | 3.13 |
| chromadb | 向量库（持久化） | 已装 |
| sentence-transformers | BGE embedding | 已装 |
| numpy | 数值 | 已装 |
| pypdf | PDF 文本提取（文本型 PDF） | 6.21.2 |
| PyMuPDF | PDF 页渲染为图片（扫描型 OCR 用） | 2.0 |
| rapidocr-onnxruntime | 扫描 PDF 的 OCR 识别 | 已装 |
| fontTools | PDF 字体编码解析（可选辅助） | 已装 |

> **扫描型 PDF 自动回退**：`kb_manager.py` 先用 pypdf 提取文本，若提取过少（<200 字，判定为扫描件），自动用 PyMuPDF 渲染每页 + RapidOCR 识别后入库。因此**文本型与扫描型 PDF 都能处理，无需手工区分**。
> **OCR 质量抽检**：`backend\app\scripts\_ocr_spotcheck.py` 可对任意扫描课标抽样页重新 OCR 复核质量（内置 4 个代表课标的抽检页）。历史抽检结论见 `docs\评审记录_E1-E5.md` §E1。

**模型下载（首次）**：`BAAI/bge-small-zh-v1.5` 默认从 huggingface 下载。若网络受限，设置镜像：
```powershell
$env:HF_ENDPOINT="https://hf-mirror.com"
```
模型缓存于 `C:\Users\<user>\.cache\huggingface\`。

## 6. 常见问题排查

| 现象 | 原因与解决 |
|---|---|
| 报 `We couldn't connect to huggingface.co` | 网络无法访问 huggingface，先执行 `$env:HF_ENDPOINT="https://hf-mirror.com"` |
| `--search` 提示"向量库不存在" | 还没入库，先跑 `--update` |
| 某 PDF 入库后片段很少 | 若是扫描件，OCR 提取量少，可提高 `OCR_DPI`（默认 200）重入库；若是加密/异常 PDF，检查能否正常打开 |
| 扫描型 PDF 未走 OCR | 确认安装了 `PyMuPDF` 与 `rapidocr-onnxruntime`；`parse_pdf` 会按提取字数自动判断 |
| 新增了文件但 `--update` 不显示"新增" | 检查文件名是否被 §1.1 的排除词命中，或文件已在库且未变 |
| 改了文件但 `--update` 显示"更新"却片段没少 | 属正常，旧块删除后新块入库，片段数可能变化 |

## 7. 数据合规（对应开发前文件 §6）

- 所有课标/量表/案例均来自公开权威来源（教育部课标、高校公开量表、教学案例），可信链接清单见 `knowledge_base/外部权威资料/外部资料可信链接清单.md`；
- 向量库仅存**文本特征与元数据**（非原始视频/人脸/语音），无隐私风险；
- 用于内测与参赛材料时，说明资料来源与版权归属。
