# 管理后台搭建计划书（SoybeanAdmin + FastAPI）

> 项目：《面向师范生试讲的多模态智能评价 Agent》
> 文档定位：管理后台（前端壳子）的搭建计划，业务逻辑全部在 FastAPI + Agent 侧
> 原则：比赛聚焦 Agent 本身，后台只是"让评委看到系统可管理、可展示"的壳，不过度工程化
> 版本：v1.0　|　日期：2026-10-25

---

## 一、目标与边界

### 1.1 要做什么
基于 SoybeanAdmin（Vue3 + Vite + Element Plus）搭建一个管理后台，把现在散落在单页 HTML 里的功能统一到一个专业后台框架里，包含三类页面：
1. **师范生试讲评价页**：上传视频 → 看评价报告 → 看成长曲线/短板热力图
2. **知识库管理页**：查看/上传/删除课标、评课量表、优秀课例，测试检索效果
3. **老师数据看板页**：班级维度分布图、学生列表、集体弱项识别

### 1.2 不做什么（明确边界，避免过度工程化）
- ❌ 不做登录/注册/权限体系（比赛演示不需要，直接进系统）
- ❌ 不做用户管理 CRUD（比赛只有 demo 数据）
- ❌ 不做操作日志/审计/回收站（非核心）
- ❌ 不做主题切换/多语言（中文单语言即可）
- ❌ 业务逻辑不搬到前端：所有评价、RAG、记忆计算都在 FastAPI，前端只调接口填表格/画图

## 二、技术栈

| 层 | 选型 | 说明 |

## 三、页面规划（共 4 个一级菜单）

### 3.1 首页（dashboard）
- 系统概览卡片：累计试讲次数、知识库文档数、用户数、最近一次评价分数
- 最近试讲记录列表（最近 5 条）
- 快速入口按钮：上传试讲 / 知识库管理

### 3.2 试讲评价（核心页）
**左侧表单区**：
- 用户ID、学科、课题、课型、学段、时长
- 视频上传组件（Element Plus Upload）
- 折叠区：测试快捷路径（粘贴 ASR/OCR 文本）

**右侧结果区**：
- 总分大数字 + 四维评分条
- 短板标签
- 分段式细节评语（时间轴定位）
- 训练规划
- **成长曲线**（ECharts 折线图：D1-D4 随次数变化）
- **短板热力图**（ECharts 热力图：18 二级指标 × 试讲次数）

### 3.3 知识库管理
**文档列表表格**：
| 列 | 说明 |
|---|---|
| 文件名 | 课标/评课量表/课例 |
| 类型 | PDF / MD |
| 片段数 | 向量化后的 chunk 数 |
| 入库时间 | |
| 操作 | 删除 / 查看原文 |

**上传区**：
- 选文件（PDF/MD）+ "入库"按钮 → 调后端入库接口
- 检索测试框：输入关键词，显示召回的 top5 片段

### 3.4 老师数据看板
**班级概览卡片**：
- 全班平均分、各维度平均分
- 集体弱项（低于 2.5 分的指标，红色标注）

**图表区**：
- 维度分布雷达图（D1-D4 全班平均）
- 二级指标热力图（学生 × 指标，色深=强弱）
- 学生列表表格：姓名 / 总分 / 趋势 / 连续短板

> 注：当前只有 demo_user 一个测试用户，看板先用现有数据 + 模拟 2-3 个学生数据做演示，阶段4 内测后替换真实数据。

## 六、开发步骤与里程碑

### 阶段 A：基础搭建（第1-2天）
1. 复制 SoybeanAdmin 模板到 `D:\2thAgent\frontend-admin\`
2. 去掉登录/权限守卫，配置路由直进首页
3. 配置 Axios baseURL 指向 `http://127.0.0.1:8000`
4. 跑通 dev server，确认能调通后端 `/health`

**验收**：打开后台，左侧菜单 4 项，点进去是空白页但不报错。

### 阶段 B：试讲评价页（第3-4天，核心）
1. 写评价表单页（视频上传 + 元信息）
2. 写结果展示区（评分 + 短板 + 时间轴评语 + 训练规划）
3. 接入 ECharts：成长曲线折线图 + 短板热力图
4. 接 `/api/evaluate_video`，端到端跑通真实视频

**验收**：上传一次函数视频，后台显示完整评价报告 + 成长曲线 + 热力图。

### 阶段 C：知识库管理页（第5天）
1. 后端写知识库 CRUD 接口（列表/上传/删除/检索测试）
2. 前端写文档表格 + 上传区 + 检索测试框
3. 测试：上传一份评课量表 MD，立即入库并可检索

**验收**：后台里上传新评课标准，下次评价就能检索到。

### 阶段 D：老师看板页（第6天）
1. 后端写班级聚合接口（从记忆表 GROUP BY）
2. 前端写雷达图 + 学生表格 + 弱项卡片
3. 用现有 demo 数据 + 模拟 2 个学生做演示

**验收**：打开看板，看到班级维度分布图和学生列表。

### 阶段 E：联调与演示准备（第7天）
1. 去掉所有 SoybeanAdmin 默认示例页面（home/manage/monitor 等模板页）
2. 清理菜单，只留我们的 4 个页面
3. 测试完整演示流程：打开后台 → 上传视频 → 看报告 → 看成长 → 切到知识库 → 切到看板
4. 写演示脚本

**验收**：能独立完成现场演示，不报错。

## 七、演示部署方案

比赛现场两种方式：

### 方式1：开发模式（简单，推荐）
- 终端1：`uvicorn app.main:app --port 8000`（后端）
- 终端2：`pnpm dev`（前端 dev server，端口 9527）
- 浏览器开 `http://127.0.0.1:9527`

### 方式2：生产模式（更稳定）
- 后端 `uvicorn` 跑 8000
- 前端 `pnpm build` 打包成静态文件，FastAPI 挂载 `/admin` 路径
- 只开一个 8000 端口，访问 `http://127.0.0.1:8000/admin`

> 比赛建议方式2，只起一个服务，故障点少。

## 八、风险与取舍

| 风险 | 应对 |
|---|---|
| Node.js/pnpm 环境没装 | 提前确认，SoybeanAdmin 需要 Node 18+ 和 pnpm |
| 前端构建失败 | 先在现有 console 目录跑通 dev，再复制到项目里 |
| ECharts 集成不熟 | SoybeanAdmin 通常自带 ECharts 示例，复制改配置 |
| 老师看板数据不足 | 用模拟数据演示，明确标注"内测后替换真实数据" |
| 比赛现场网络问题 | 所有依赖本地安装，不依赖 CDN；HF 离线模式 |
| 前后端跨域 | FastAPI 已开 CORS，无需额外处理 |

## 九、与现有单页的关系

现有 `frontend/index.html`（单页）保留，作为：
- 快速测试用（改完后端接口，直接开单页验证，不用等前端 dev server）

管理后台是"正式演示界面"，单页是"开发测试界面"。
