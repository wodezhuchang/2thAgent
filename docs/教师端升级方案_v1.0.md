# 教师端升级方案 v1.0

> 项目：师范生试讲智能评价 Agent
> 定位：把教师端从"只看待复评、只提交复评意见"升级为"掌握所带学生学情、数据驱动复评"的工作台。
> 原则：**不做大重构**，保持现有架构稳定；全部复用工作流已沉淀的 evaluation / expert_review / progress / training_plan / calibration 数据。

---

## 一、背景与目标

教师端原仅有三个页面：班级学情看板（dashboard）、待复评列表（review-list）、单次复评（review）。
其中班级看板的学生列表只有 `user_id / 平均分 / 最近一次` 三列，信息量不足以支撑教师了解学生。

工作流已经积累了大量可复用数据（历次分数、四维维度、短板、专家复评记录、机器-专家差异、训练计划），
但教师端几乎没有利用。本方案目标是：

1. 让教师能看到"绑定给自己的学生"的完整学情；
2. 让复评决策有数据支撑（先看背景、再复评）；
3. 沉淀并可视化机器 vs 专家差异，反哺复评侧重点。

## 三、阶段 1 落地详情

### 3.1 后端：教师名下学生聚合接口

**新增 `GET /api/teacher/{teacher_id}/students`**（`backend/app/main.py`）
复用 `memory_store.get_teacher_students_dashboard`（`backend/app/memory/memory_store.py`）。

返回结构：
```json
{
  "teacher_id": "teacher_1",
  "count": 2,
  "students": [
    {
      "user_id": "demo_user",
      "name": "师范生小张",
      "last_score": 38.8,        // 最近一次总分（0-100）
      "avg_score": 41.2,         // 历史平均分
      "delta": 4.9,              // 最近 vs 上次 差值
      "trend": "up",             // up / down / flat
      "weakest_dim": "D1",       // 最近一次最弱维度
      "weakest_value": 1.75,     // 最弱维度得分（0-5 分制）
      "pending_count": 15,       // 待复评数（未 auto_pass/expert_reviewed/returned）
      "review_count": 2,         // 已专家复评次数
      "trial_count": 16,         // 试讲次数
      "last_at": "2026-10-29"    // 最近一次试讲日期
    }
  ]
}
```

数据口径：仅取该教师 `teacher_student` 绑定的学生；最弱维度取自最近一次 `scores_json` 的 D1-D4 total（0-5 分制）最小值；
待复评数 = 该学生 evaluation 中 `review_status IS NULL 或不在 (auto_pass, expert_reviewed, returned)` 的条数。
