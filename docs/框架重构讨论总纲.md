## 一、当前框架现状速览

### 已有模块（已跑通）
- **输入**：学生上传试讲视频（异步任务）+ 元数据（学科/课题/课型/学段/时长）
- **多模态感知**：ASR / OCR / 姿态估计 / 教学时间轴
- **RAG 检索**：Chroma + BGE-small-zh，元数据标签 `doc_type`（curriculum/rubric/case/rule/recycled_case）+ `subject`（学科/general）
- **主链（LangGraph）**：parse → perceive → retrieve → memory_read → evaluate(D1-D4) → synthesize → evidence_check → triage(A/B/C) → reflect → memory_write → finalize
- **分流器**：A 自动过 / B 教师抽审弱维 / C 强制教师复评（按时长分档应用硬规则）
- **双回流闭环**：
  - 环1：争议课例脱敏入向量库（recycle.py，阈值总分差≥8或维差≥2）
  - 环2：数值校准 offset（≥5样本后算均值偏移）
- **教师端**：复评工作台、退回机制、消息通知
- **前端**：学生端报告页、教师端复评页、管理后台

### 技术栈
- 后端：FastAPI + LangGraph + ChromaDB + SQLite
- 前端：Vue3 + Naive UI（Soybean 模板）
- 模型：BGE-small-zh-v1.5（embedding）、Whisper（ASR）、RapidOCR、MediaPipe（姿态）、LLM（评课）

## 二、五篇论文研读后暴露的疏漏清单

按"严重程度 × 改动量"排序，分为 P0（必须补）/ P1（应该补）/ P2（可以做）/ P3（未来工作）。

### P0 — 逻辑断环，不补答辩讲不通

#### 1. 闭环方向偏了：回流是"改进系统"，不是"改进学生"
- **现状**：两个回流环（争议案例入RAG库 + 数值校准）都在让"系统打分更准"，没有一条链从评价结果回到"学生下次练什么"
- **证据来源**：多智能体论文对比发现，人家是"训练数据→进步曲线→发现瓶颈→推送针对性资源"的学生成长闭环；我们是"评价完报告给出去，学生下次怎么练系统不知道"
- **具体表现**：training_plan 字段写了 next_focus + specific_tasks，但只是一次性建议，下次上传时系统不会主动说"你上回D3板书是短板，这次重点练板书"

#### 2. 课型/学段标签入库了但 RAG 没真用上
- **现状**：graph.py 调 retrieve 时只传了 subject，lesson_type 和 grade_level 没加进 where 过滤
- **证据来源**：CST2 论文把课型/学段作为差异化核心维度；我们标签打了一半在数据库里睡觉
- **影响**：物理实验课和物理习题课召回的课标上下文一模一样

#### 3. 没有"训练前"环节，RAG 库只在评价时被利用
- **现状**：学生上传视频前系统零介入；RAG 库里的课标/课例只被当成"LLM评分参考"
- **证据来源**：多智能体论文第一块就是"教学准备"——协同过滤给学生推荐教学设计模板；ClassMind 也是先给学生看课程材料
- **改进方向**：学生选了学科+课题后，先推 3 条优秀课例 + 对应课标要点，再让他录

#### 4. RAG 召回可能被 LLM 忽略，没有强制锚定
- **现状**：把课标片段扔进 context 就完事，LLM 可能按通用经验打分
- **证据来源**：EduPanel 和 ClassMind 都在 prompt 里强制"必须引用召回的第N条作为依据"
- **改进方向**：打分前让 LLM 先输出"本课专属评分要点"，再按要点打分

### P1 — 有明确差距，补了能显著提升质量

#### 5. 没有热点检测，全视频均匀处理
- **现状**：对整个10分钟试讲均匀跑感知流水线
- **证据来源**：ClassMind 的 AVA-Align 框架——先识别"热点片段"（导入/提问/板书/小结），只对热点深度分析，省token且聚焦
- **改进方向**：先用规则/小模型定位教学关键片段，再重点分析

#### 6. 个别化诊断太粗，缺硬指标
- **现状**：feedback 是 LLM 自由生成，没有 TTT 教师话语占比、提问类型分布、平均句长等硬指标
- **证据来源**：多智能体论文用 YIN/A计权/Emotion2vec/BERT 做细粒度诊断；ClassMind 做 COPUS 编码 + Bloom 提问分类
- **改进方向**：在 ASR 文本上后处理算硬指标（不额外调用大模型）

#### 7. 反馈没做时间戳可点击跳回视频
- **现状**：timeline_feedback 有时间戳，但前端不能点击跳播
- **证据来源**：ClassMind 每条 feedback 都可跳回视频片段；EduPanel 也是带 timestamp 的
- **改进方向**：前端把 timeline_feedback 的 timestamp 做成可点击跳播

#### 8. 置信度太粗（0.3/1.0两档×0.8固定值）
- **现状**：evidence_check 里证据成功率只有两档（有数据=1.0，没数据=0.3），RAG支持度写死0.8
- **证据来源**：Smarter Together 做了细粒度置信度估计（基于答案一致性+解释一致性），EduPanel 做了 planted error 实验
- **改进方向**：RAG支持度改成 top-k 召回的平均距离；证据成功率按数据质量分档（ASR置信度、OCR字数、姿态检测置信度）

#### 9. 视觉维度可能系统性偏松，没监控
- **现状**：D3板书、D4教态靠 VLM/姿态模型打分
- **证据来源**：EduPanel 实测发现 VLM 看视觉内容会偏宽容（视觉维度平均偏高+0.67）
- **改进方向**：数值校准环专门监控"视觉维度 offset 是否长期为正"

#### 10. 没有 planted error 实验量化教师介入效果
- **现状**：做了 A/B/C 分流，但没量化过"教师到底能不能发现 AI 错了"
- **证据来源**：EduPanel 植入26个错误测专家识别 AUC=0.77；Smarter Together 做了 flip rate 分析
- **改进方向**：人工改10个AI分数，看教师能不能识破——这是答辩时最硬的实验数据

---

### P2 — 锦上添花，时间充裕再做

#### 11. 进步追踪可视化弱
- **现状**：memory_store 有 progress 表，但前端没做"学生历次折线图"
- **证据来源**：多智能体论文强调进步曲线；ClassMind 有历史对比页

#### 12. 反馈自验证不够具体
- **现状**：reflect 节点做幻觉检查，但没"把反馈和视频片段交叉验证"
- **证据来源**：ClassMind 的 self-consistency validation 是把生成的反馈拿回去和对应时间戳视频核对

#### 13. 数值校准是全局偏移，没分学科
- **现状**：所有学科共用一个 offset
- **证据来源**：CST2 论文不同学科评分标准不同；物理老师偏严、语文老师偏松是不一样的
- **改进方向**：按 subject 分组算 offset

#### 14. 回流只回流"分歧案例"，没回流"高分优秀案例"
- **现状**：只有人机分歧课例入 RAG 库
- **证据来源**：正负样本平衡才能让 RAG 库既有"反面教材"也有"正面示范"

---

### P3 — 未来工作，写进论文展望

#### 15. 没有训练中实时反馈
- **证据**：多智能体论文核心卖点是讲课过程中即时反馈（语速/音量/音调）
- **现状**：录播后整体评价
- **未来方向**：如果以后做直播训练模式，把 perceive 流水线搬到流式处理

#### 16. 没有模拟学生互动
- **证据**：多智能体论文有 BDI 模拟学生智能体
- **现状**：无生录播
- **未来方向**：互动情景模拟

### 对进度安排的微调建议
- 阶段2和阶段3之间应该加一步：**先做小样本验证**——挑5-10段试讲视频，改完框架后先跑一遍，看分流率/回流率/校准偏移是否合理，再全量改造
- 阶段3"模拟训练调优"要明确：我们没有专门的训练数据，所谓调优其实是：
  - 调 prompt（评课维度的 system prompt）
  - 调阈值（分流阈值、回流阈值、置信度阈值）
  - 调 RAG 检索参数（top-k、chunk大小、where过滤）
  - 不是真的 fine-tune LLM
- 阶段4操作手册要包含：环境搭建、数据准备、知识库入库、启动后端/前端、常见问题

#### 讨论1：调分器模块（已确认设计）

**核心逻辑（用户纠正后）：**
学生上传视频时指定老师 → 系统检查该老师有没有专属参数组 → 有则按该老师参数打初评，没有则按默认参数打初评 → 老师复评 → 复评数据自动更新该老师参数组 → 下次初评更接近该老师评分习惯。

**参数组设计：**
```
calibration_profiles 表
├── profile_id
├── name（"系统初始参数" / "王老师评分参数"）
├── bound_expert_id（绑定的老师ID，默认参数为 null）
├── mode（auto / manual）
├── offsets_json（全局/分维度/分学科偏移）
├── thresholds_json（分流/回流阈值）
├── sample_count（该参数积累了多少条复评）
├── status（collecting 积累中 / active 激活使用）
├── is_default
└── created_at / updated_at
```

**触发逻辑：**
- 学生上传时带 expert_id → 查 calibration_profiles 找 bound_expert_id 匹配的参数组
- 找到且 status=active → 用该参数组打初评
- 没找到或 status=collecting → 用默认参数打初评，同时标记"该老师参数积累中"
- 老师复评提交后 → 自动更新该老师参数组的 offsets
- 某老师样本攒够 5 条 → status 自动从 collecting 切为 active

**初始参数：** 用 10 段已带专家评分的视频跑出一版全局参数作为"系统初始参数"（默认参数组）。

**管理后台页面：** 放 frontend_Admin → 系统管理 → 校准中心
- 参数码卡片列表，支持切换/编辑/复制/删除
- 自动模式：根据专家复评自动更新
- 手动模式：管理员拖动滑块调整

**已确认：**
- ✅ 多组参数码切换值得做（答辩展示点）
- ✅ 放在管理后台
- ✅ 10个视频够训练初始参数
- ✅ 核心逻辑：按指定老师匹配参数组打初评

#### 讨论2：chat 模块（已确认设计）

**现状：**
- 学生端 chat：已有完整实现，角色是"试讲陪练朋友"，有意图识别，会读用户历史画像
- 教师端 chat：已有 expert_chat，会读学生画像、会按意图查RAG课标

**教师端 chat 改进点：**
1. **帮写评价建议 = 给初稿润色**，不是从零生成
   - 教师输入初稿 → chat 润色 + 补充建议
   - 同时主动查找该学生**经常出问题的地方**、**明显出问题的地方**，提醒教师关注
   - 保证教师问 chat 后得到的是真正正确的内容（基于学生历史数据+课标，不是 LLM 瞎编）
2. **RAG 检索加 subject 过滤**（现在没传，会召回跨学科课标）
3. **防泄露校验**：教师只能看自己绑定的学生数据

**学生端 chat 改进点：**
1. **去掉写死的人名"杨德琰"**，改成通用角色（"你的试讲陪练朋友"），角色定位不变
2. **学生端 chat 不加 RAG**，优秀课例不在 chat 里返回
   - 优秀课例放在"课前瞻优"学生端页面展示（推荐课例+对应课标总结单）
   - chat 里可以返回优秀课例的**链接**，点击跳转到"课前瞻优"页面

#### 讨论3：硬指标具体算哪些

补2确认要做，但具体算哪些需要对齐：

| 指标 | 怎么算 | 数据来源 | 对应维度 |
|---|---|---|---|
| TTT 教师话语占比 | ASR 文本里教师说话时间占总时长比例 | ASR + 时间轴 | D2 讲授语言 |
| 提问次数 | ASR 文本匹配提问词表 | ASR | D1 教学设计 |
| 提问类型分布 | 封闭式提问 vs 开放式提问（按句尾词/句式分类） | ASR | D1 教学设计 |
| 平均句长 | ASR 文本按句子切分，算平均字数 | ASR | D2 讲授语言 |
| 板书字数 | OCR 输出字数 | OCR | D3 板书 |
| 互动次数 | 学生发言次数（靠说话人分离或ASR标注） | ASR | D1 教学设计 |

#### 讨论3：硬指标（已确认）

6个硬指标确认够用：
- TTT 教师话语占比
- 提问次数
- 提问类型分布（封闭/开放）
- 平均句长
- 板书字数
- 互动次数

**注意：硬指标设计要把握平衡**
- 过少过松 → 检查不出问题
- 过多过拘泥于学科 → 一堂课常见教学方法在另一堂课被判错
- 阈值设定要跨学科通用，不做学科特定的硬性规则

#### 讨论5：元报告 + 任务清单（已确认设计）

**现状问题：**
- 历史分数曲线、维度曲线已经有了（元数据层）
- 但缺"真实可行的内容"——学生读完报告要自己想干什么
- 现在的报告全是不足的改进建议，没有对技能掌握不错的**肯定**

**要新增的任务清单页面：**
- 前端新页面：每条任务前面有圆圈，完成后打勾
- 新上传试讲后，根据本次报告+上次不足动态生成任务
- 任务条数控制：不要求很多，正常录课频率前差不多能完成
- 动态更新：多对比上次的不足，给可行计划

**关于"肯定"部分的约束：**
- 报告里要有对掌握不错的技能的肯定
- **但绝对不能硬说好**，避免幻觉虚假报告
- 肯定必须有证据支撑（比如"D2 讲授语言：语速适中、表述清晰，ASR 转写准确率高"）

**实现方式：**
- 每次新评价完成后，LLM 生成任务清单（基于本次短板+上次未完成任务）
- 存在 training_plan 表，前端任务清单页读取
- 下次上传时，上次未完成的任务自动带入

### 最终框架确认（2026-11-07）

用户手绘图已对照确认，四点修正：

1. **A/B/C 标注修正：**
   - A 路 = 高置信度（证据齐全）→ 自动过（不是"高分"）
   - B 路 = 低置信度维度 → 教师抽审弱维（不是"中等"）
   - C 路 = 硬风险触发 → 强制复评（不是"高分歧"）

2. **B 路再拆一层：** B 路里置信度 ≥0.6 的自动过（报告标注证据偏弱），<0.5 的才给教师看。实际给教师比例远低于 70%。

3. **四维识别区分硬指标和 LLM：**
   - 硬指标（TTT/提问次数/提问类型/平均句长/板书字数/互动次数）在 LLM 之前用代码算
   - LLM① 只打主观维度
   - 硬指标结果直接作为客观分

4. **调分器模块加入主链：**
   - 位置：LLM①原始分 → 调分器 → 校准后机器初评分
   - 逻辑：学生指定老师后，查该老师参数组，有则按该老师参数打初评，无则按默认参数

### 后端主链
```
学生上传(meta+video+expert_id)
  ↓
parse → perceive(ASR/OCR/姿态/时间轴)
  ↓
硬指标计算(代码) → 客观分
  ↓
RAG检索(where过滤 subject+doc_type)
  ↓
LLM①主观打分 → 原始分
  ↓
调分器(查该老师参数组 → 校准偏移)
  ↓
综合四维分 + 置信度
  ↓
A/B/C分流:
  A: 高置信度 → 自动过
  B: 低置信度维度 → 置信度≥0.6自动过 / <0.5教师抽审
  C: 硬风险触发 → 强制复评
  ↓
reflect(幻觉检查) → memory_write(落库)
  ↓
finalize(报告+RAG命中备注)
```

### 回流闭环
1. **争议课例回流**：教师复评后，分差≥8或维差≥2且有评语 → 脱敏入RAG，doc_type=case, case_quality=disputed
2. **优秀课例回流**：专家分≥85且无分歧 → 脱敏入RAG，case_quality=good
3. **调分器参数更新**：教师复评数据自动更新该老师参数组，攒够5条激活

### 元报告闭环
- 每次新评价完成后，LLM②生成元报告（历次报告总结）
- → 动态生成任务清单（可打勾，条数控制在正常录课频率前可完成）
- → 下次上传时带入上次未完成任务
- 报告内容：有不足改进建议 + 有证据支撑的肯定（不硬说好）
