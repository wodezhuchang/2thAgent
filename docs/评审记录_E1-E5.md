## E1｜知识库可检索性与数据完整性（阶段1）

### 判据（评审前定义）

1. **数据完整性**：knowledge_base 下所有非排除文档全部入库，无数据缺口（扫描型 PDF 亦需通过 OCR 补全）。
2. **可检索性**：对课标/量表/细则的自然语言查询，能召回语义相关的正确片段，来源元数据（学科/课标名）正确。
3. **增量正确性**：未变文件在重跑时自动跳过；新增/修改文件自动入库/更新。
4. **OCR 质量**：扫描型 PDF（义务教育课标）识别文本可读、语义正确、可被检索命中。

### 实测证据

**① 数据完整性（缺口归零）**

| 指标 | 之前 | 现在 |
|---|---|---|
| 扫描文档数 | 49 | 49 |
| 已入库文档数 | 33 | **49**（全覆盖） |
| 向量片段数 | 6,579 | **12,423** |
| 数据缺口（未入库） | 16 | **0** |

验证方式：`_check_gap.py`（独立脚本，不依赖入库脚本输出）统计"扫描文件"与"向量库 source_file"之差，结果 0。

**② 可检索性（语义召回）**

- 查询 `义务教育数学课程标准对核心素养的要求`，过滤 `subject=数学`，top3：
  - **top1 dist=0.1178**，来源 `外部权威资料/义务教育_数学_义务教育数学课程标准2022年版.pdf`，命中"核心素养，体现正确价值观、必备品格和关键能力…"
  - top2 dist=0.1554，同来源，命中"核心素养导向的课程目标…"
  - top3 dist=0.1844，来源 `普通高中_数学_…2017年版2020年修订.pdf`（高中课标，相关）
- 结论：跨学段同课题相关片段正确召回，来源元数据（学科/学段）精确。

**③ 增量正确性（重跑验证）**

- 一次全量 `--update` 输出：**新增 16 / 更新 0 / 跳过 33**。
- 已入库的 33 个文档（高中课标+3量表+14案例+评课细则）因内容未变被正确"跳过"，仅 16 个新扫描件入库 → 增量去重机制验证正确，不会重复入库。

**④ OCR 质量（抽样人工复核）**

对 4 个代表性扫描课标各抽 2 页（前部+中部）重新 OCR 复核：

| 课标 | 抽检页 | 识别质量 | 备注 |
|---|---|---|---|
| 数学（189页） | p4 前言、p60 课程内容 | 优 | "双减政策/百分数/扇形统计图"等专业表述准确 |
| 英语（201页） | p5 前言、p90 学段特征 | 优 | 英文混排（7~9年级）识别正确 |
| 科学（193页） | p4、p100 学业要求 | 优 | "天然材料/人造材料"准确 |
| 历史（86页） | p4、p50 学习主题 | 优 | "物质文化遗产/非物质文化遗产"准确 |

- 仅见极个别形近字瑕疵（如"自已"应为"自己"），不影响语义与检索，可接受。
- **结论：OCR 质量达标，无需人工逐页复核。**

### 结论

E1 **通过**。知识库 49 文档 / 12,423 片段全部入库、无缺口；语义检索跨学段命中正确、来源元数据精确；增量机制正确；扫描课标 OCR 质量达标。阶段1可进入阶段2（LangGraph 智能体主干）。

### 遗留问题 / 备注

- 个别扫描课标（数学/科学/英语超长页）OCR 含极少量形近字错字，若后续作为**引用原文**输出需谨慎，可考虑对该片段的"关键表述"二次校对；用于检索召回无影响。

## E2｜智能体主干：规划 / 记忆 / RAG链路 / 轨迹（阶段2）

### 判据（评审前定义）

1. **图编排正确**：Plan 主链（parse→retrieve→memory_read→evaluate→synthesize→reflect→memory_write→finalize）端到端跑通，各节点状态正确传递。
2. **记忆闭环**：SQLite 五表读写正确；跨轮次对比能判断进步/退步/持平（trend）。
3. **RAG 注入生效**：评价基于检索到的课标/量表/课例，不凭空打分（有证据引用）。
4. **轨迹可观测**：append-only 轨迹日志生成，可回放。
5. **真实 LLM 输出质量**：按 JSON Schema 输出，评语专业、可落地、无幻觉。

### 实测证据

**① 图编排（mock LLM 验证）**

- 9 节点图构建成功；`run_agent` 端到端跑通，trace 步骤完整：`rag_retrieve→memory_read→evaluate→synthesize→reflect_ok→memory_write→finalize`。
- mock 验证 6 次 LLM 调用（4 维 + 合成 + Reflexion），overall_percent 权重合成正确（0.25/0.30/0.20/0.25），scores 键对齐 schema。

**② 记忆闭环（真实 LLM，两次运行）**

| 轮次 | 总评分 | trend | 对比 |
|---|---|---|---|
| 第一次 | 46.0 | first_try | 无历史，判断正确 |
| 第二次（改进版） | 56.6 | **improved** | 提升10.6分，四维全升（设计1.5→2.25、语言2.8→3.4、板书2.5→3.25、教态2.0→2.4），vs_previous_try_id 正确关联 |

- SQLite 落库验证：`get_prev_evaluation` 正确返回最近一次评价与短板；`get_user_trials`、`training_plan` 读写正常。
- **结论：跨轮次"短板追踪 + 进步对比"闭环真实跑通。**

**③ RAG 注入生效（真实 LLM）**

- 第一次评价短板引用"数学抽象、数学建模、直观想象、数学运算等**课标核心素养**"——这些来自检索到的数学课标片段。
- 训练规划 reference_case 引用优秀课例；评价未出现脱离师范规范的凭空论断。

**④ 轨迹可观测**

- 每次运行生成 `backend/data/traces/<try_id>.jsonl`，append-only，含各节点步骤与关键中间结果。

**⑤ 真实 LLM 输出质量（DeepSeek，key 存 .env 不硬编码）**

- 完整 JSON 输出对齐 schema（scores 四维+overall、timeline_feedback、weaknesses、progress_compare、training_plan）。
- 评语专业可落地（如"提问缺乏启发性，候答时间不足""板书缺少结构性，未突出知识脉络""目标—活动—评价一致性不足"）。
- 未发现幻觉或违背评课标准论断。

### 结论

E2 **通过**。智能体主干具备规划（Plan 主链）、检索（RAG）、记忆（SQLite 跨轮次闭环）、反思（Reflexion）、可观测（轨迹日志）五类智能体能力，真实 LLM 输出专业且闭环跑通。阶段2可进入阶段3（多模态感知工具集成）。Web 界面为阶段2 附属项，进度见交付说明。

### 遗留问题 / 备注

- **Web 界面（FastAPI+前端）尚未完成**——阶段2 验收标准含"基础交互页面"，将在阶段3 前补齐（见任务13）。
- **checkpointer 短期记忆**：当前用 GraphState 内存传递，生产化可加 LangGraph checkpointer（SQLite MemorySaver）实现断点续跑，阶段4 前落地。
- **四维并行**：当前四维评价为串行遍历（逻辑等价），阶段3 接入多模态后改为 LangGraph fan-out 真并行。
- 真实评价质量受 LLM 温度与转录质量影响，阶段4 内测校准权重与锚点。

## E3｜多模态感知工具集成（阶段3）

### 判据（评审前定义）

1. **工具注册表可插拔**：ToolSpec + ToolRegistry 支持 register/unregister/list/call，单工具可独立卸载/更换，工具调用有可观测钩子。
2. **感知工具真实可用**：ASR（语音）/OCR（板书）/时间轴（环节）/姿态（教姿）四类工具均从**真实试讲视频**自动提取信号，而非依赖人工输入或 mock。
3. **图改造四维并行**：评价阶段从串行改为并行 fan-out，多模态信号经工具调度注入评价，非只看文字脚本。
4. **感知数据落盘（可追溯）**：每个试讲的感知原始结果持久化到感知档案（含姿态关键点序列），可追溯、可复现、可对比。
5. **端到端闭环**：上传视频 → 感知 → RAG → 记忆 → 四维并行评价 → 合成 → 记忆写入 → 报告，全流程真实跑通。

### 实测证据（全部基于真实视频 `mypreteaching_fore.mp4`，"一次函数"3 分钟试讲）

**① 工具注册表可插拔**
- 4 个感知工具 + RAG 检索工具均经 `registry.call` 调度；`unregister→重新注册` 热插拔验证通过。
- `add_on_call_hook` 钩子在图运行时把工具调度写入轨迹日志（trace_logger），保证可观测。

**② 感知工具真实可用（逐工具真实视频实测）**

| 工具 | 技术 | 真实结果 |
|---|---|---|
| ASR `asr_transcribe` | faster-whisper 1.2.1（small/int8/CPU，PyAV 锁 13.1.0） | 365 字 / 50 段 / **322 词级时间戳**；wpm=105、口头禅"然后×8"、停顿 15 次（D2 信号） |
| OCR `ocr_board` | ffmpeg 抽帧 + RapidOCR | 识别"一次函数 y=kx+b 斜率截距、y=2x+1、y=-3x、y=x²+2"；跨帧去重（117 框→30 行）；公式/手写有误差但足供 D3 |
| 时间轴 `timeline_slice` | 关键词规则 + 环节单向推进约束 | 导入 1.6-16.9s / 新授 19.7-105s / 练习 105.7-174.3s / 小结 174.8-180.6s，与视频内容吻合 |
| 姿态 `pose_analyze` | MediaPipe 1.1.1 **新版 tasks API**（1.1.1 移除旧 mp.solutions）+ 官方 pose_landmarker_lite.task | 19/20 帧检测；手势均值 4.24/活跃度 4.04、最大倾斜 16.81、面向变化 0.637（D4 信号）+ 每帧 33 关键点序列 |

**③ 图改造：四维并行 + 工具调度**
- 新增 `node_perceive` 节点（parse 之后）：有 video_path 时经工具注册表统一调度 ASR/OCR/时间轴/姿态，无则沿用前端多模态（skip 正确）。
- `eval_all_dimensions` 由串行遍历改为 `ThreadPoolExecutor` 并行（LLM 调用 IO 密集、线程安全）。
- **端到端真实验证**：传入真实视频，trace 显示 4 工具全部调度成功（asr 322词 / ocr 35行 / pose 19帧 / timeline 4环节），多模态信号全部进入评价（asr_text 365字 / board_text 217字 / 4环节 / 8姿态指标）。

**④ 感知数据落盘（可追溯）**
- 新增 `senses_store.py`，四个工具原始结果落盘至 `datasets/demo_preteaching/senses/*.json`：

| 感知档案 | 大小 | 保存内容 |
|---|---|---|
| `asr.json` | 36KB | 完整语音文本 + 50 段 + 322 词时间戳 + 语音特征 |
| `ocr.json` | 1.2KB | 板书识别文本 + 检测框 + 置信度 |
| `timeline.json` | 8.8KB | 教学环节时间轴 |
| `pose.json` | 85KB | **33 关键点 × 19 帧序列**（含 x/y/z/visibility）+ 聚合指标 |

- 姿态工具不只输出聚合指标，**保留每帧 33 个关键点序列**——满足"姿势数据可查"需求（答辩可据此可视化骨架）。

**⑤ 端到端闭环**
- 单次完整运行：感知（4 工具，98s）→ RAG 检索 → 记忆读取 → 四维并行评价 → 合成 → Reflexion → 记忆写入 → 报告，全流程真实跑通。
- 真实输出：overall=43.2，D1=2.0 / D2=2.2 / D3=2.25 / D4=2.2；短板与训练规划专业可落地。

### 结论

E3 **通过**。多模态感知工具链（ASR/OCR/时间轴/姿态）全部基于真实视频实测可用；图改造实现四维并行 fan-out + 经工具注册表调度多模态信号；感知数据统一落盘（含姿态关键点序列）可追溯可复现；上传视频→多维度综合分析→报告的完整链路端到端闭环跑通。阶段3可进入阶段4（内测迭代）。

### 遗留问题 / 备注

- **ASR 模型下载依赖网络**：当前 huggingface.co 直连不通，靠缓存/`HF_ENDPOINT=hf-mirror.com` 规避；生产/演示环境需预置模型缓存（阶段4 固化）。
- **OCR 对公式/手写边界**：y=x²+2 识别为 y=×+2、"斜率"识别为"斜梓"，系 OCR 已知边界；已作为 D3 评价的容错依据，不阻塞功能。
- **姿态仅单人检测**：`num_poses=1`，若试讲视频含学生互动画面需确认主人物，阶段4 可加"主人物跟踪"。
- **感知耗时 98s**（ASR 为主）：长视频处理需在界面提示等待，任务进度提示（开发前文件 §5 风险项）阶段4 落地。
- **LLM 四维并行可能触发限流**：若 DeepSeek 并发限制，可回退串行（保留配置开关），阶段4 内测观察。
